## Code Review Findings

### Strengths

- Domain-oriented NestJS modules and shared packages give the monorepo understandable boundaries; Prisma centralizes data access and typed models.
- Authentication is deny-by-default via a global `AuthGuard`; public routes require explicit `@Public()`. Production startup rejects missing Keycloak configuration, and configured tokens are verified against remote JWKS with issuer and optional audience checks.
- Controller-level RBAC is widespread, and recent commits explicitly fixed cross-guideline ownership validation and database uniqueness constraints.
- Baseline API protections include Helmet, configured CORS, DTO validation/whitelisting, global throttling, structured logging, metrics, and a global exception filter.
- Upload handling checks size, MIME allowlists, and magic bytes. Storage operations are abstracted behind an S3 service.
- Database access seen in the focused review uses Prisma APIs and tagged `$queryRaw` for the health probe; no obvious string-built SQL injection was found.
- Test breadth is good on paper: 80 unit/component/E2E/performance test files cover auth, services, FHIR projections, exports, storage, UI workflows, and Playwright user journeys.
- ADRs document FHIR schema, module boundaries, rich-text editing, RBAC, asynchronous exports, and FHIR facade choices. Operations documentation covers migration, rollback, backup, recovery, incidents, and on-call response.

### Findings

1. **P0 — Stored cross-site scripting in the public reader.** `PublicGuidelineReader.tsx` passes database-backed section content directly to `dangerouslySetInnerHTML`. String content is returned unchanged, while object content is `JSON.stringify`-ed without HTML escaping; either can contain executable markup. Because the source is an unauthenticated published-guideline endpoint, malicious or compromised author content can execute in every public reader’s origin. Render the TipTap document through a safe schema renderer or sanitize with a strict allowlist, and add hostile-content tests plus a restrictive CSP.

2. **P0 — API container/startup is tied to one host address.** `apps/api/src/main.ts` calls `app.listen(port, '100.110.64.57')`. That address is a host Tailscale IP and generally does not exist inside the API container; it also contradicts Docker health checks that connect to `localhost:3000`. Make the bind host configurable and default server/container execution to `0.0.0.0` (or the platform-appropriate interface), while controlling exposure through published ports/firewalls.

3. **P1 — Bearer tokens are accepted in query strings for every protected route.** The global auth guard accepts `?token=` as an unconditional fallback, although the comment says it exists for SSE/EventSource. Query tokens leak more readily through URLs, access logs, browser history, referrers, and monitoring. Limit this mechanism to the specific streaming route, prefer a short-lived single-purpose ticket/cookie, and redact token query parameters in logs.

4. **P1 — Docker workspace manifests are incomplete.** Both application Dockerfiles copy root, API, web, FHIR, and UI manifests before `npm ci`, but the root workspace glob also includes `apps/e2e` and `packages/widget`. Missing workspace manifests can invalidate reproducible install/build behavior as the lockfile evolves. Copy every workspace manifest (or narrow workspace/package installation deliberately) and exercise both Docker builds in CI.

5. **P1 — Staging is image publication, not deployment.** `deploy-staging.yml` pushes images on every main commit, but the Helm deployment job is commented out. The workflow name and production-oriented assets overstate the verified delivery path. Wire an environment-gated atomic Helm deployment with smoke/rollback checks, or rename the workflow to reflect build-only behavior.

6. **P1 — No regression test was found for public rich-text safety.** The web suite is broad, but the file inventory contains no `PublicGuidelineReader` test. Add rendering tests for script tags, event handlers, dangerous URLs, nested TipTap JSON, and valid allowed formatting.

7. **P2 — OIDC audience enforcement is optional.** Signature, issuer, and expiry are verified, but `AUTH_EXPECTED_AUDIENCE` may be empty. Production validation should require the expected API audience to prevent accepting a valid token minted for another client/resource server.

8. **P2 — Development auth is intentionally forgeable when OIDC variables are absent.** Outside `NODE_ENV=production`, arbitrary syntactically valid JWT payloads are decoded without signature verification. This is tested and logged, but dangerous in shared demos/staging or environments with a mistyped `NODE_ENV`. Prefer an explicit opt-in flag confined to test/local modes and fail closed otherwise.

9. **P2 — Dependency maintenance is fragmented.** Twenty-seven dependency PRs include duplicate root/workspace updates and numerous majors. Static manifests show coherent current versions, but the backlog makes patching status hard to reason about. Consolidate Dependabot strategy and require migration notes for majors.

10. **P2 — Floating container tags weaken reproducibility.** CI/E2E and Compose use tags such as `minio/minio:latest`, `minio/mc:latest`, and application `latest`. Pin immutable versions/digests, especially for CI and production dependencies.

11. **P2 — CI is coupled to one self-hosted runner.** Every primary workflow job targets `[self-hosted, mravps]`. This may be intentional, but it creates a single-runner availability and trust boundary. Document runner hardening/capacity and consider GitHub-hosted jobs for non-deployment checks.

12. **P3 — Repository metadata is incomplete.** The package is private and versioned `0.0.1`, while the README license is `TBD`. Choose a license, add the license file, and clarify release/versioning/support policy before calling the project open source.
